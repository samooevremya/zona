# Задание Клоду: графика деревни новичков B, пакет v1

Пользователь уже поручил тебе внедрение UI B/2. Этот пакет ДОПОЛНЯЕТ его окружением. Не откатывай текущие изменения и не подменяй новую игру архивом 0.4. Подключи к актуальной сборке; 0.4 ниже используется только как карта исходных точек интеграции.

## Состав и ограничения
28 элементов в четырёх PNG-атласах: 4 земли, 4 строительных материала, 16 объектов, 4 крыши. props/roofs имеют настоящую прозрачность. manifest.json содержит фактические source rectangles без пустых полей и логические размеры. Изображения 1254×1254; разрешение элементов превышает нужное ×2, не увеличивать игровые размеры. Атласы предназначены для drawImage(sourceRect), не для показа целиком на карте.

Это первая партия графики для интеграции, не готовая переписанная игра. Изображения созданы генерацией; есть небольшие перспективные условности у забора и дымоходов, поэтому забор отображать как узкую полосу. Транспорт сжимается до существующего footprint (машина 64×24, автобус128×64); при заметном искажении выбрать contain в заданной области, НЕ расширять коллизию молча. Три кроны вместо восьми уникальных: заполнить 8 прежних вариантов вращениями/зеркалами с небольшим изменением масштаба. Нет новых людей/портретов/мебели бункера/мутантов. Нет новой карты и механики. Пламя, дым, свет и погода берутся из существующего кода.

## Порядок подключения
1. Загрузить manifest.js и village-renderer.js до запуска игры; await new VillageArt().load() до paintGround/buildCanopy/buildRoofs. При ошибке загрузки оставить прежнюю графику, вывести понятное сообщение в консоль; не останавливать игру.
2. Не использовать fetch manifest.json для локального file://: manifest.js уже содержит данные. В однофайловом финальном HTML встроить картинки data:image/png;base64 и заменить images[*].file на эти строки; встраивать JS/manifest до IIFE. При внешнем наборе держать относительные пути к assets рядом с HTML.
3. g4.js paintGround: заменить заливки GR/DI/AS текстурами grass/dirt/asphalt; TR/BU рисовать на grass; чередовать grass_dry крупными пятнами. Полы FL/CF — floor_wood/floor_concrete. Стены BR/CO — wall_brick/wall_concrete; сохранить старые южные грани/тени. Не затирать статические объекты текстурой после их отрисовки.
4. Для масштаба текстуры использовать 256 игровых px (8 клеток) на исходный фрагмент; не сжимать весь фрагмент до клетки32×32. VillageArt.fill привязывает фазу текстуры к мировым координатам. Helper pattern делает зеркальный повтор: математическая бесшовность исходных генераций не гарантируется. Для границ GR/DI использовать edge шириной 8–12 игровых px, только по травяной стороне, плюс редкие tuft. Не накладывать переходы на стены/полы. Не менять типы клеток SOLID/OPAQ.
5. buildCanopy: сохранить 72×72 игровые px, исходный центр (36,36), деревья поверх персонажей и крыш как сейчас; полупрозрачность при перекрытии игрока сохранить. Сделать backing canvas144×144 с ctx.scale(2,2), отрисовывать в мире72×72. Кусты 36×36 и трава24×24 — нижний декоративный слой. Не раскидывать траву каждый кадр: seeded размещение один раз.
6. buildRoofs: четыре крыши подставить вместо процедурной заливки. Размер W=h.w*T+10, H=h.h*T+10; backing canvas2W×2H; изменить последующий drawImage так, чтобы размер назначения оставался W×H, иначе крыши удвоятся. Сохранить h.a, roofHidden, прозрачность при входе и старую привязку (h.x*T-3,h.y*T-3). Прозрачные дырки roof_broken не закрашивать.
7. drawStaticObj: заменить car,bus,hatch,fire на соответствующие спрайты. x/y у объектов — левый верх: передавать центр x+w/2,y+h/2. crateDraw — ящик26×26 и прежняя индикация тайника. fire_base рисовать центром FIRE.x,FIRE.y; не дублировать пламя. Для stash заменить графику в drawCaches (g7), сохраняя условия раскрытия/обыска.
8. Новый декор fence/barrel/logs/rubble/bench не должен сам менять пути NPC. Расставить вручную вне дорожек и дверей или оставить чисто декоративным, без нового solid. Для баррелей/заборов с реальной коллизией требуется отдельное согласование игровой карты, этого пакет не делает.
9. Сохранить освещение: наши изображения без сильных внешних теней; старую тень объектов использовать один раз. Проверить, что финальное зерно/виньетка/цветовой фильтр не съедают детали; сначала уменьшить силу зерна примерно вдвое и сравнить, не удалять ночь.
10. Миникарта: сохранить fog и метки; при желании взять уменьшенную groundC как подложку, не рисовать случайную географию. Бункер справа не должен попасть в карту открытого Кордона.

## Проверка и сдача
- Та же карта, двери, обход препятствий NPC, сохранение, торговля и новый HUD.
- День, ночь, дождь; персонаж различим на траве и грунте.
- Вход/выход во все шесть домов: крыша исчезает и возвращается, пол виден.
- Нет чёрных прямоугольников у PNG, соседних объектов из атласа, мерцания краёв, удвоения размеров.
- 844×390 и 390×844, DPR2, тайники/машина/автобус на прежнем месте.
- Не создавать один canvas всей карты в2×: исходный размер4224×3520 уже около59MB RGBA, при2× около238MB. Использовать исходный groundC или чанки512px с backing1024, только при необходимости и с ограничением кэша. Не перегенерировать землю в каждом кадре.
- Проверить загрузку без сети у итогового одиночного HTML.
Прислать пользователю HTML, исходники ZIP, скрин деревни днём и с открытой крышей. Не выдавать галерею из пакета за скрин работающей игры.
